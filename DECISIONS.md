# DECISIONS — решения и противоречия спецификации

> Обновлено после реализации (Sprint 0–3 и админка). Новые решения — D-16 и далее, ADR по стеку — A-01…A-05.

Источник истины — `CLAUDE_CODE_SPEC.md` (v1.0). Здесь зафиксировано всё, где спецификация противоречива, неполна или неоднозначна, и выбранный вариант. Каждое решение покрыто тестом или конфигом. **Помеченные ⚠ ждут подтверждения владельца продукта.**

## Проверка архитектуры: результат
Граф теста реализован как данные (`src/features/quiz/config`) и проверен `src/tests/unit/graph.test.ts` (26 тестов):
- 29 шагов (включая `RESULTS`), ID уникальны, граф ацикличен, всё достижимо из `COMMON.Q1`, единственный сток — `RESULTS`;
- 400 комбинаций Q1×Q2×Q3×Q4 → 35 700 полных путей до `RESULTS`, тупиков нет; в каждой не-home комбинации меню направлений содержит ≥ 2 (на деле ≥ 3) пункта;
- `Q4=home` никогда не попадает во внешние ветки;
- назад/смена ответа очищает downstream; сериализация и восстановление черновика; stale `schemaVersion`.

## Принятые решения

| # | Тема | Проблема в спецификации | Решение |
|---|---|---|---|
| D-01 | Расположение | В исходном репозитории был другой проект (Personal OS). | Проект вынесен в отдельный репозиторий `aidainde`. |
| D-02 | «Strictly-indoor» направления | §5: «для outside не показывать strictly-indoor», но какие — не сказано. | Для `outside` скрыты `venues`, `wellness` (остаются walks, games, culture); для `indoor` скрыт `walks`; `any` — без ограничений. Скрытые доступны через «Показать все направления» с `mismatch: true`. Список — константа `HIDDEN_BY_SETTING` в `direction.ts`. ⚠ |
| D-03 | Меню при 5 кандидатах | «До четырёх» направлений, при `any` кандидатов 5. | Показывается топ-4 по баллам; пятое — через «Показать все». |
| D-04 | Размер семьи | §7: диапазон 1–30, но «1 в family возможен только после смены companion». | Для `family` диапазон 2–30; для `group` 3–30. |
| D-05 | Экран BASIS | §7: показывать для всех, кроме `solo`. При бюджете `free`/`any` вопрос бессмыслен. | Пропускаем при `free` и `any`. При пропуске `budgetBasis` = `per_person` (в `finalizeAnswers`). Правило в одном месте: `tailVisibility['COMMON.BASIS']`. ⚠ |
| D-06 | Длина теста | §3: «максимум 11 экранов». Но обязательные экраны + условные хвосты дают до 14 (Games + family + выбор даты). Минимум 8. | Условия графа из §5–§7 приоритетнее оценки. Лимит 11 не соблюдается; сокращать можно только решением владельца (напр. убрать DATE_PICKER в отдельный модал). ⚠ Тест фиксирует границы 8…16. |
| D-07 | PARTY_SIZE | §7: «или для специфического формата» — формат не определён. | Только `group` и `family`. |
| D-08 | TRANSPORT | §7: «или система хочет рекомендовать загородную» — недетерминировано. | Только `W1=escape` или `W2=outskirts`. |
| D-09 | Порядок хвоста | Требуется неизменный порядок. | `TAIL_ORDER` в `config/common.ts`; видимость — `visibilityRule`. |
| D-10 | Производные значения | `partySize` для solo/friend/partner, `budgetBasis` для solo. | Не хранятся как ответы; добавляются `finalizeAnswers()` **после** валидации (иначе считались бы лишними). |
| D-11 | «Без детей» | Представление в модели. | `childAgeBands = []`; `undefined` = ещё не спрашивали. Ввод `['4-6','none']` нормализуется в `[]`. |
| D-12 | Даты today/tomorrow/weekend | Дата определяется сервером (Europe/Moscow). | В состоянии хранится только `dayChoice`; `targetDate` — только для `date`. |
| D-13 | Смена ответа | §4 и §8.10 допускают сохранение независимых полей. | Простая полная очистка всех последующих шагов (рекомендация §8.10). |
| D-14 | Ответы вне пути | Нужна защита API. | `validateComplete` отклоняет `STRAY_ANSWER`, `INCOMPLETE`, `INVALID_ANSWER`, неизвестные ключи. |
| D-15 | Тексты BASIS | В спецификации заданы только вопрос и значения. | «На человека» / «На всех» — рабочие подписи, меняются в конфиге. |

## Пробелы данных (решить до Sprint 2–3)

| # | Пробел | Предложение |
|---|---|---|
| G-01 | Нет поля `isDemo` в схеме БД, хотя §15 его требует. | Добавить `isDemo boolean not null default false` во все контентные таблицы; production-запросы фильтруют `isDemo=false`. |
| G-02 | `activities` без `ageMin`/`ageMax`/`indoorOutdoor`, а фильтр по возрасту детей и по `home` нужен. | Добавить `ageMin`, `ageMax`; `setting='home'` подразумевается. |
| G-03 | Нет `ageMax`, а группа «13–17» требует верхней границы. | Совместимость по `ageMin` (нижняя граница объекта ≤ нижней границе группы); `ageMax` — опционально. `ageMin ≥ 18` = adult-only. |
| G-04 | `indoorOutdoor` без перечня значений. | `indoor | outdoor | both | unknown`; `unknown` не считается совпадением. |
| G-05 | Нет словаря тегов для scoring (§9 «по таблицам тегов»). | Фиксированный реестр тегов в `features/quiz/tag-map.ts`: каждому ответу — набор `tags.key`. Заводится в Sprint 3 вместе с seed. |
| G-06 | Критерий «атмосфера» (10 баллов) не имеет вопроса. | Атмосфера = `socialEnergy` + `setting` (теги group `energy`/`setting`); «энергия/интенсивность» = ответы ветки (V2, G2_PHYSICAL, R2…). |
| G-07 | `event_occurrences` упомянуты, но не описаны. | Таблица `event_occurrences(id, eventId, startsAt, endsAt, status, ticketsUrl)`; фильтр даты — по occurrence. |
| G-08 | TTL: токен «короткоживущий» (§11) vs 30 дней (§10). | 30 дней для сессии; токен хранится хэшем, rate limit на `/api/results`. |
| G-09 | ORM «Drizzle или Prisma — выбрать». | **Drizzle ORM** (лёгкий, типобезопасные запросы, подходит для Supabase/serverless). |


## Решения при реализации

| # | Тема | Решение |
|---|---|---|
| D-16 | Название продукта | Рабочее «Куда сегодня?» заменено на **«ӘЙДӘ ИНДЕ!»** (дизайн-кит). Внутренние идентификаторы не менялись. Заголовок главной остался по спецификации: «Хм, чем бы заняться в Казани?». |
| D-17 | Домашние идеи | Показываются **только** при `setting=home`; при остальных вариантах «где» подборка состоит из мест и событий. Спецификация не говорит, нужны ли домашние идеи при «Неважно», выбрано консервативное правило (§8.2: дом ≠ городской клуб и наоборот). |
| D-18 | Нижняя навигация | В кит заложены Главная / Карта / Избранное / Билеты, но карты, избранного и билетов в MVP нет. Использованы четыре иконки: Главная, Подбор, Каталог, О сервисе. На странице теста панель скрыта. |
| D-19 | Кнопки ответа в тесте | Кит требует круглых кликабельных элементов; ответы бывают в 2 строки. Использован `--radius-l` (28 px): при одной строке получается «таблетка», при двух — скруглённая плашка. |
| D-20 | Фото | Дизайн-кит запрещает фото в карточках списка; фото показывается только на странице записи и только при подтверждённых правах. Без фото — иллюстрация из кита (плитка), фиктивные фото не используются. |
| D-21 | Карта | Встроенной карты нет: ссылка на Яндекс Карты по адресу/координатам (без трекеров и лишних запросов). |
| D-22 | Токены результатов | Токен — 24 случайных байта (base64url, 32 символа), в БД только HMAC-SHA256. Сессия живёт 30 дней (G-08), при открытии результаты **пересчитываются** по актуальному каталогу, а дата («сегодня/завтра/выходные») берётся зафиксированной в момент выдачи; прошедшая дата помечается. |
| D-23 | Изменение ответов из результатов | Ссылки «Изменить дату/бюджет/тип» ведут на `/quiz?from=<токен>&step=<id>`: прежние ответы подгружаются по токену, в адресе ответов нет, токен из адреса сразу убирается. |
| D-24 | Подборка: стадии | Строго (направление + все подвиды) → без подвида → соседние направления; «Похожие идеи» маркируются, смягчённые критерии перечисляются. Возраст, дата, вместимость и точный бюджет не смягчаются никогда. Неизвестная цена уходит в блок «Стоимость уточняется» (кроме бюджета «Неважно»). |
| D-25 | Возраст и вместимость | Известная вместимость — жёсткий фильтр; неизвестная не считается «подходит всем» (заметка «Размер компании уточняйте»). Возраст детей: нет пересечения — исключить, частичное — пометить; для семьи с детьми объект 18+ исключается всегда. |
| D-26 | Бюджет | Сравнивается нижняя граница цены с лимитом в базисе пользователя (на человека/на всех). Если единица цены неизвестна, берётся наиболее мягкая трактовка. Цена `0` — бесплатно; `NULL` — неизвестно, это разные значения. |
| D-27 | Форматированный текст | `stepsRichText` хранится как простой текст (абзацы, списки «- ») и рендерится React без HTML — XSS невозможен по построению. |
| D-28 | Коды ошибок | К кодам спецификации добавлены `FORBIDDEN`, `INVALID_QUERY`, `INVALID_CONTENT`, `PUBLISH_REQUIREMENTS`, `SLUG_TAKEN`, `INTERNAL_ERROR`. Конверт тот же: `{error:{code,message,details?}}`. |
| D-29 | Демо в production | Demo-записи исключены на уровне запросов, если не выполнено `ALLOW_DEMO_CONTENT=true` **и** деплой не production (`VERCEL_ENV`/`APP_ENV`). Сид с `--demo` в production отказывается работать. |

| D-30 | Погода | Пороги: гроза, порывы ≥ 20 м/с, мороз ≤ −25 °C, жара ≥ 35 °C — «опасно»; осадки (код или вероятность ≥ 60 %), порывы ≥ 14 м/с, мороз ≤ −15 °C — «плохо». Для диапазона берётся худший день. Штраф к баллу уличных вариантов: 10 / 25. При опасной погоде показываются до 3 вариантов в помещении, не вошедших в основную выдачу; настройку «где» сами не меняем (§8.6 требует подтверждения). |
| D-31 | Аналитика | Только суммы по дням (таблица `metrics_daily`): пройдено тестов, пустые подборки, направления, «где», компания. Без токенов, IP, ответов целиком и сторонних скриптов. |
| D-32 | Импорт и запуск | Импорт создаёт черновики; публикует человек. Заглушки `[…]`, демо и дубликаты отклоняются. `content:check` — барьер перед запуском. |
| D-33 | CSP | Скрипты только свои, шрифты — Google Fonts (как в ките), картинки — свои и из `IMAGE_HOSTS`, формы и соединения — на свой домен, `frame-ancestors 'none'`. |
| D-34 | Статус 404 | `loading.tsx` не применяется к карточкам записей: потоковая отдача превращала бы «не найдено» в код 200 (мягкий 404). Только каталог и результаты. |
| D-35 | Тестовый вход | `E2E_AUTH=1` включает вход по куке для автотестов админки; приложение не запускается, если флаг включён на production. |

## ADR: отклонения от стека

| # | Решение | Причина |
|---|---|---|
| A-01 | Без shadcn/ui; компоненты — из дизайн-кита (CSS-классы `k-*`) | Кит содержит готовые компоненты с жёсткими значениями; shadcn добавил бы второй конкурирующий набор стилей. |
| A-02 | Tailwind 3 с пресетом кита, подключены только утилиты (без Preflight) | Пресет кита рассчитан на v3; Preflight перебил бы стили кита. |
| A-03 | TypeScript 5.9 | `typescript-eslint` не поддерживает TS 7: без этого не работает линтер. |
| A-04 | Drizzle ORM + локальный PGlite для разработки и тестов | Одна ORM (требование G-09); SQL-тесты идут на настоящем Postgres-движке без отдельной инфраструктуры. PGlite вынесен из бандла (`serverExternalPackages`). |
| A-05 | Шрифты Onest и Unbounded **размещены на нашем домене** (`public/fonts`, `src/styles/fonts.css`), `@import` Google Fonts из кита убран | Google Fonts бывает медленным или недоступным для аудитории из России, плюс лишние запросы к третьей стороне; лицензия OFL разрешает. Токены кита не менялись, CSP строже. |
| A-06 | Ограничитель запросов с подключаемым хранилищем (память / Upstash Redis REST) | Память инстанса на serverless не даёт общей защиты; Redis по HTTP не требует драйвера. Сбой Redis → автоматический откат на память. |

## Известные ограничения и что осталось

- **Админка не проверена с реальным Supabase**: нет ключей. Проверено в браузере с тестовым входом: весь сценарий редактора (черновик → предпросмотр → публикация → снятие → удаление), роли, защита доступа, форма. Не проверен только сам вход Supabase Auth: пройдите его один раз вручную.
- Ограничение частоты по умолчанию в памяти инстанса; для общей защиты подключить Upstash (см. README).
- Нет автоматического сжатия и загрузки фото: админка принимает ссылки на разрешённые домены.
- Нет настоящего контента: каталог пуст до наполнения (ориентир ≥ 50 проверенных записей, §15). Юридическую редакцию политики данных нужно утвердить.
