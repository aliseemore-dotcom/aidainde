# ӘЙДӘ ИНДЕ! — куда сходить в Казани

Веб-сервис подбора досуга: человек отвечает на несколько вопросов (настроение, компания, место, направление, дата, бюджет) и получает **детерминированную** подборку реальных мест, событий и домашних идей из собственного каталога. Без нейросетей, без выдуманных данных.

Документы: [Спецификация](CLAUDE_CODE_SPEC.md) · [План](IMPLEMENTATION_PLAN.md) · [Граф теста](QUIZ_GRAPH.md) · [Решения и противоречия](DECISIONS.md) · [Дизайн-код](design-kit/DESIGN_CODE.md)

Стек: Next.js (App Router) · TypeScript · Tailwind (пресет дизайн-кита) · Postgres (Supabase) + Drizzle ORM · Zod · Vitest · Playwright.

## Быстрый старт

```bash
npm install
cp .env.example .env.local      # для локальной работы достаточно ALLOW_DEMO_CONTENT=true
npm run dev                     # http://localhost:3000
```

Без `DATABASE_URL` приложение само поднимает встроенную БД PGlite в `.pglite/`, применяет миграции, заводит словарь тегов и (при `ALLOW_DEMO_CONTENT=true`) **демо-записи**. Все демо-записи вымышлены, помечены `isDemo=true` и подписаны «Демо, вымышленная запись».

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Postgres (Supabase). Пусто — локальный PGlite (на боевом деплое без неё приложение не стартует) |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Вход в админку (Supabase Auth). Нет значений — админки нет |
| `RESULT_TOKEN_SECRET` | Секрет для хэшей токенов результатов, **16+ символов**, обязателен в production |
| `ALLOW_DEMO_CONTENT` | `true` — показывать demo. На production игнорируется |
| `IMAGE_HOSTS` | Разрешённые https-домены картинок для админки |
| `LOG_RECOMMENDATIONS` | `true` — писать выданные рекомендации в `recommendation_logs` (без ПД) |
| `NEXT_PUBLIC_SITE_URL` | Адрес сайта для sitemap/OpenGraph |
| `APP_ENV` / `VERCEL_ENV` | `production` включает боевые ограничения |

Секреты не используют префикс `NEXT_PUBLIC_` и не попадают в репозиторий.

## База данных

```bash
npm run db:migrate              # применить миграции к DATABASE_URL
npm run db:seed                 # словарь тегов (безопасно для production)
npm run db:seed -- --demo       # + демо-записи (в production запрещено)
npx drizzle-kit generate        # новая миграция после правки src/db/schema.ts
```

RLS включён на всех таблицах и **политик нет**: прямой доступ через Supabase API закрыт, приложение читает данные только с сервера и всегда фильтрует `status='published'`.

## Наполнение каталога

```bash
npm run content:import -- файл.json --dry-run   # только проверка файла
npm run content:import -- файл.json             # запись как ЧЕРНОВИКИ (публикует человек в админке)
npm run content:import -- файл.json --publish   # сразу публиковать то, что проходит правила
npm run content:check                           # перед запуском: нет demo, у опубликованного есть дата проверки
```
Формат — `content/TEMPLATE.json`. Записи с незаполненными заглушками вида `[ЦЕНА]`, демо-записи и дубликаты slug не загружаются. Импорт ничего не выдумывает: данные нужно собрать и проверить по первоисточнику.

## Админка

1. В Supabase → Authentication создайте пользователя (email + пароль).
2. Выдайте права: `npm run admin:make -- <uuid-пользователя> [editor|admin]`.
3. Откройте `/admin/login`.

Роли: **editor** — создаёт, правит, публикует, снимает с публикации; **admin** — дополнительно удаляет. Публикация требует: название, slug, описание, тег-направление, источник, адрес (место), время (событие). У события обязательна дата проверки `verifiedAt`: без неё оно не попадёт в подборку. Предпросмотр черновика — `…?preview=1` (только для вошедшего редактора). Все изменения пишутся в `audit_log`. На обзоре — «Требует внимания» (события без свежей проверки, завершённые, непроверенные места) и приватные счётчики за 14 дней.

Фото: только с `https` и только с доменов из `IMAGE_HOSTS`; при правах «не подтверждены» фото на сайте не показывается.

## Тесты и качество

```bash
npm run typecheck && npm run lint
npm test                 # unit + integration (SQL на PGlite)
npm run build && npm run test:e2e   # Playwright: мобильный (390px) и десктоп, включая axe WCAG AA
```

Что покрыто: все 400 комбинаций Q1×Q2×Q3×Q4 до результата; назад/смена ответа; восстановление черновика; границы суток и выходных по Казани; жёсткие фильтры (возраст, вместимость, 18+, отменено/распродано, дата, 0 ₽ против «цена неизвестна», дом против заведения); скоринг, fallback, разнообразие; токены, срок жизни, ошибки API; права админки и защита от CSRF; сценарии из §14 спецификации; доступность.

## Как устроена подборка

1. **Кандидаты** — только `published` (события также без отменённых и распроданных сеансов).
2. **Жёсткие фильтры** — дата/сеанс, возраст, вместимость, улица/помещение/дом, транспорт, точный бюджет. Никогда не ослабляются автоматически.
3. **Баллы 0–100** — направление и подвид 35, настроение 20, компания 15, энергия 10, атмосфера 10, бюджет 5, полнота данных 5; неприменимые критерии нейтральны, неизвестные теги совпадением не считаются.
4. **Fallback** — сначала смягчается подвид, затем соседние направления; пользователю показывается, что смягчено («Похожие идеи»).
5. **Разнообразие** — не более двух карточек одной узкой подкатегории, если есть альтернатива в пределах 15 баллов.
6. **Объяснение** — «Почему подходит» строится только из подтверждённых совпадений; наличие мест не обещается.

Таблица соответствия ответов тегам — `src/features/recommend/tag-map.ts`; словарь тегов — `tag-registry.ts`.

## Погода

Прогноз Open-Meteo (без ключа, Казань) учитывается, если он есть: плохая погода опускает уличные варианты (не удаляет), опасная — предупреждает и показывает варианты в помещении, выбор пользователя не меняется. Сбой источника, таймаут (2,5 с) или мусор в ответе — подборка работает без погоды с нейтральной подсказкой «Проверьте погоду». Пороги — `src/lib/weather.ts`.

## Деплой (Vercel + Supabase)

1. Создайте проект Supabase, возьмите строку подключения Postgres и ключи API.
2. Локально: `DATABASE_URL=… npm run db:migrate && npm run db:seed`.
3. В Vercel задайте переменные из таблицы выше (`RESULT_TOKEN_SECRET`, `DATABASE_URL`, ключи Supabase, `IMAGE_HOSTS`, `NEXT_PUBLIC_SITE_URL`). `ALLOW_DEMO_CONTENT` на production не включайте.
4. Выдайте права редактору (`admin:make`) и наполните каталог.
5. `DATABASE_URL=… npm run content:check` — перед запуском проверка каталога.
6. Пройдите полный путь на боевом домене: demo-записей быть не должно.

Ограничение частоты запросов хранится в памяти инстанса: это защита от случайных всплесков. Для распределённой защиты подключите общий стор (Upstash/Redis) в `src/lib/security.ts`.
