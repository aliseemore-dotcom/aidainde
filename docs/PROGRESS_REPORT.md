# Отчёт о выполненной работе — ӘЙДӘ ИНДЕ!

Дата: 12.10.2026 · Репозиторий: https://github.com/aliseemore-dotcom/aidainde (ветка `main`, приватный)

## 1. Что за проект
Мобильно-первичный веб-сервис подбора досуга в Казани. Человек отвечает на 8–14 вопросов (социальная энергия, компания, настроение, «где», направление, дата, бюджет) и получает персональную подборку **существующих** мест, событий и домашних идей из собственного каталога. Подборка **детерминированная, без нейросетей**: каждое совпадение можно объяснить. Есть свободный каталог `/explore`, админка для ручного наполнения и заглушка `/date` («Скоро запустим»). Бронирования, платежи, личные кабинеты и парсинг сайтов вне MVP.

Исходники: техническая спецификация (`CLAUDE_CODE_SPEC.md`, в репозитории) и дизайн-кит «ӘЙДӘ ИНДЕ!» (токены, компоненты, логотип, иллюстрации).

## 2. Стек
Next.js 16 (App Router) · TypeScript 5.9 · Tailwind 3 (пресет кита, только утилиты) · PostgreSQL (Supabase) + Drizzle ORM · Zod · Vitest · Playwright (+axe) · PGlite (локальная БД и SQL-тесты) · Supabase Auth (только админка) · Open-Meteo (погода). Деплой — Vercel (ещё не выполнен).

## 3. Что сделано

**Тест (граф вопросов).** Вся логика ветвления — чистые функции, не в React: 29 шагов, 6 тематических веток + дом, условные экраны (дата, бюджет, на человека/на всех, размер группы, возраст детей, транспорт) в фиксированном порядке. Состояние сериализуемо, версия схемы `schemaVersion`, смена ответа очищает зависимые шаги. UI: один вопрос на экран, «Назад», кнопки «назад/вперёд» браузера, черновик в localStorage на 24 ч, клавиши 1–9, фокус на заголовке, индикатор словами без ложных процентов.

**Движок рекомендаций** (`src/features/recommend`). Жёсткие фильтры: дата/сеанс, возраст (18+ исключается для семьи с детьми), вместимость, улица/помещение/дом, транспорт, точный бюджет (на человека/на всех). Баллы 0–100 (направление 35, настроение 20, компания 15, энергия 10, атмосфера 10, бюджет 5, полнота данных 5), неприменимые критерии нейтральны, неизвестные теги совпадением не считаются. Fallback: смягчается подвид, затем соседние направления («Похожие идеи»), возраст/дата/вместимость/строгий бюджет не смягчаются никогда. Разнообразие (не более двух из одной подкатегории). «Почему подходит» строится только из подтверждённых фактов, наличие мест не обещается. Цена `0` и «цена неизвестна» — разные вещи; неизвестная цена уходит в блок «Стоимость уточняется». Погода учитывается, если есть прогноз (плохая опускает уличные варианты, опасная предупреждает и предлагает варианты в помещении); при сбое источника подборка работает без неё.

**Данные и API.** Схема БД (места, события, сеансы, идеи на дом, теги, медиа, сессии, логи, админы, аудит, дневные счётчики), RLS включён без политик. API: `POST /api/quiz/complete`, `GET /api/results/:token`, `GET /api/catalog`, карточки по slug, админские CRUD. Единый формат ошибок, лимиты запросов, непрозрачный токен результатов (в БД только HMAC-хэш, сессия 30 дней), дата «сегодня/завтра/выходные» считается на сервере по Казани (Europe/Moscow), ответы не попадают в URL.

**Страницы.** Главная (3 входа), `/quiz`, `/results`, `/explore` (фильтры, поиск, пагинация), карточки места/события/идеи, `/date` (заглушка), `/about`, `/privacy`, 404, страница ошибки, состояния загрузки/пусто/ошибка сети.

**Админка.** Вход через Supabase Auth, роли editor/admin. CRUD с публикацией и черновиками, предпросмотр черновика, «снять с публикации», теги из единого словаря, фото (только https и разрешённые домены, права обязательны для показа), журнал изменений. Публикация требует обязательных полей; у события — дата проверки `verifiedAt`. Защита от CSRF, обзор «Требует внимания» (события без свежей проверки, завершённые, непроверенные места) и приватные счётчики.

**Наполнение и запуск.** Импорт из JSON (создаёт только черновики, отклоняет заглушки вида `[ЦЕНА]`, демо и дубликаты), `content:check` как барьер перед запуском. Демо-записи вымышлены, помечены `isDemo` и подписаны; на production они не показываются никогда.

**Безопасность и SEO.** CSP и заголовки, `robots`/`sitemap`, OpenGraph, `noindex` для админки и результатов.

**Дизайн.** Токены, компоненты, логотип (только готовые SVG) и иллюстрации из кита; нет «сырых» цветов и теней, кроме `--shadow-float`.

## 4. Проверка качества
- **137 unit/integration-тестов** (Vitest, SQL на PGlite): граф теста и все 400 комбинаций Q1×Q2×Q3×Q4, state machine, границы суток и выходных по Казани, жёсткие фильтры, скоринг, fallback, разнообразие, погода (включая сбои), каталог, токены и сроки жизни, права админки, CSRF, импорт, счётчики, форма админки.
- **84 E2E-прогона** (Playwright, 42 сценария × мобильный 390px и десктоп): полный путь теста до подборки, изменение ответов из результатов, каталог и фильтры, 404, вход и CRUD редактора, роли, **проверка доступности axe WCAG A/AA** на всех страницах.
- `typecheck`, `eslint`, production-сборка — без ошибок. CI (GitHub Actions) настроен.
- Найдены и исправлены в процессе: потеря истории браузера из-за перезаписи `history.state`; падение страниц админки до редиректа; PGlite в бандле Next; мягкие 404 из-за `loading.tsx`; несоответствие линтера и TypeScript 7.

## 5. Решения и отклонения от спецификации (подробно — `DECISIONS.md`)
- Самый длинный путь теста — 14 экранов вместо «максимум 11»: обязательные условные экраны из спецификации дают именно столько (минимум 8).
- Размер семьи 2–30 (в спецификации 1–30, но 1 запрещён); вопрос «на человека/на всех» пропускается при бюджете «Бесплатно/Неважно».
- Какие направления «строго indoor» при «На улицу» не определено — принято: скрыты «Заведения» и «Спокойный отдых».
- Домашние идеи показываются только при выборе «Дома».
- Без shadcn/ui (кит содержит свои компоненты); TypeScript 5.9 (линтер не поддерживает 7); нижняя навигация из 4 пунктов вместо «Карта/Избранное/Билеты».
- Дополнены пробелы схемы: `isDemo`, `ageMax`, таблица сеансов, словарь тегов, коды ошибок.

## 6. Что не сделано / риски
1. **Нет реального контента**: каталог пуст без демо (нужно от 50 проверенных записей). Данные не выдумываются.
2. **Не проверен живой вход Supabase Auth** (нет ключей): весь остальной сценарий админки проверен в браузере через тестовый вход, который не работает на production.
3. **Не развёрнуто**: нет домена, Vercel и боевой БД; мониторинг не подключён.
4. Политика данных — рабочий текст, нужна юридическая редакция.
5. Ограничение частоты запросов хранится в памяти инстанса (для распределённой защиты нужен Redis/Upstash).
6. Открытые продуктовые вопросы: длина теста 14 экранов, список «строго indoor», пропуск вопроса про базис бюджета.
7. Вне MVP: полноценный DateQuiz, Telegram-бот, бронирование, парсинг.

## 7. Как запустить
```bash
git clone https://github.com/aliseemore-dotcom/aidainde.git && cd aidainde
npm install
echo "ALLOW_DEMO_CONTENT=true" > .env.local
npm run dev          # http://localhost:3000, встроенная БД и демо-данные
npm test && npm run build && npm run test:e2e
```
Деплой: Supabase (`DATABASE_URL`, ключи), `npm run db:migrate && npm run db:seed`, переменные Vercel, `npm run admin:make -- <uuid>`, `npm run content:check`. Подробно — `README.md`.

## 8. Следующие шаги
Получить ключи Supabase и домен → проверить вход вручную → наполнить каталог → `content:check` → деплой на Vercel → пройти путь на боевом домене.
